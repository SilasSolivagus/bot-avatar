# M1.5 — Content-Addressed Cache and Pack Boundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the string-derived ETag with an opaque content tag, make the `304` path skip rendering entirely, and move pack validation from "field checks at startup" to "parse at the boundary plus exhaustive conformance over the pack's finite data domain".

**Architecture:** Three structural changes, each removing a class of failure rather than guarding against it. (1) A pack's content is hashed through a canonical serialization; that hash, plus the identity hash, size and state, is the only input to the ETag — so no untrusted string ever reaches a response header. (2) Because the tag is computable without rendering, the `304` path never builds a spec or an SVG. (3) `parsePack` is the single door: it returns a branded `ValidatedPack`, and it runs every `family × palette × state` combination through the renderer before the process starts serving.

**Tech Stack:** unchanged from M1 — Node 22, Hono 4, `@hono/node-server`, jiti, Vitest 2.

**Spec:** `docs/specs/2026-10-27-bot-avatar-spec.md` §10 (headers, ETag), §10.1 (pack boundary), §12 (service acceptance). The spec was amended for this work; the ETag is now specified as an opaque 16-hex tag carrying no pack or identity text.

## Global Constraints

- ETag is `"` + 16 lowercase hex + `"`. No pack id, pack version, identity, size or state text may appear in it.
- `X-Avatar-Pack: <packId>@<packVersion>` is informational only; it must never influence caching and must never be read by the service.
- A matching `If-None-Match` must return `304` **without** calling `buildAvatarSpec` or `renderSvg`. This is asserted by call count, not by status code.
- `packContentHash` must be identical across processes for identical pack data, and must change when any byte of the pack data changes. Canonical serialization sorts object keys recursively.
- The canonical serializer must reject or normalise values that JSON cannot represent unambiguously: `undefined`, functions, `NaN`, `Infinity`, circular references. A pack containing them fails parsing rather than hashing to something arbitrary.
- Work is bounded: the conformance sweep renders at most 1000 combinations; beyond that it samples and must say so in the log line, never silently.
- The library packages keep `dependencies` and `peerDependencies` empty. `apps/service` may take dependencies.
- No server-side response cache is introduced. The improvement comes from not rendering on a cache hit, not from storing results.

```ts
export class CanonicalError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "CanonicalError";
  }
}

/** Deterministic JSON: object keys sorted at every depth, arrays in order, unrepresentable values rejected. */
export function canonicalJson(value: unknown): string {
  return write(value, new Set<object>());
}

function write(value: unknown, seen: Set<object>): string {
  if (value === null) return "null";
  switch (typeof value) {
    case "string":
      return JSON.stringify(value);
    case "boolean":
      return value ? "true" : "false";
    case "number":
      if (!Number.isFinite(value)) throw new CanonicalError(`cannot canonicalise ${value}`);
      return JSON.stringify(value);
    case "object": {
      const object = value as object;
      if (seen.has(object)) throw new CanonicalError("cannot canonicalise a circular structure");
      seen.add(object);
      try {
        if (Array.isArray(value)) {
          return `[${value.map((entry) => write(entry, seen)).join(",")}]`;
        }
        const entries = Object.keys(object as Record<string, unknown>)
          .sort()
          .map((key) => {
            const entry = (object as Record<string, unknown>)[key];
            if (entry === undefined) throw new CanonicalError(`cannot canonicalise undefined at ${key}`);
            return `${JSON.stringify(key)}:${write(entry, seen)}`;
          });
        return `{${entries.join(",")}}`;
      } finally {
        seen.delete(object);
      }
    }
    default:
      throw new CanonicalError(`cannot canonicalise a ${typeof value}`);
  }
}
```

```ts
/** SHA-256 over the canonical form of a pack. Changes when any pack data changes, version field or not. */
export function packContentHash(pack: unknown): string {
```

### Task 3: Exhaustive pack conformance

**Files:**
- Create: `apps/service/src/conformance.ts`, `apps/service/test/conformance.test.ts`
- Modify: `apps/service/src/packs.ts`

**Interfaces:**
- Consumes: `outlinePath`, `phaseForSeed` from `@botavatar/engine`; `renderSvg` from `@botavatar/svg`.
- Produces:
  - `assertPackRenders(pack: StylePack, origin: string): { rendered: number; sampled: boolean }`
  - Throws `PackError` naming `origin`, the combination, and the offending fragment.

**Why this shape.** `buildAvatarSpec` picks family and colour from a hash, so it cannot be driven to every combination. Conformance therefore builds the `AvatarSpec` for each `(family, palette)` pair directly — the body from `outlinePath` over that family's outline, the colour from the palette entry — and renders both states. That covers every body and every colour the pack can ever produce, which is the finite part; the hash arithmetic is engine code, already covered by the library's own tests.

```ts
import type { AvatarSpec, StylePack } from "@botavatar/engine";
import { outlinePath, phaseForSeed } from "@botavatar/engine";
import { renderSvg } from "@botavatar/svg";
import { PackError } from "./packs.js";

const MAX_RENDERS = 1000;
const BAD = ["NaN", "undefined", "Infinity", "[object Object]"];

/** Every body and every colour this pack can produce, rendered once. Catches broken data before serving. */
export function assertPackRenders(
  pack: StylePack,
  origin: string,
): { rendered: number; sampled: boolean } {
  const combos: Array<{ family: number; color: number }> = [];
  for (let family = 0; family < pack.shapes.length; family++) {
    for (let color = 0; color < pack.palette.length; color++) combos.push({ family, color });
  }
  const sampled = combos.length * 2 > MAX_RENDERS;
  const selected = sampled ? combos.slice(0, Math.floor(MAX_RENDERS / 2)) : combos;

  for (const { family, color } of selected) {
    const shape = pack.shapes[family]!;
    const paletteColor = pack.palette[color]!;
    for (const state of ["idle", "working"] as const) {
      const spec: AvatarSpec = {
        packId: pack.id,
        packVersion: pack.version,
        identity: `conformance-${family}-${color}`,
        seed: family * 1000 + color,
        family,
        look: shape.look ?? family,
        color: paletteColor,
        path: outlinePath(shape.outline, {
          phase: phaseForSeed(family * 1000 + color),
          smoothingPasses: shape.smoothingPasses,
        }),
        eyes: pack.eyes.eyes,
        eyeRotation: (family * 1000 + color) % pack.eyes.rotation.modulo - pack.eyes.rotation.spread,
        durationMs: pack.motion.durationMsByFamily[family] ?? 1800,
        motionAmplitude: pack.motion.amplitude,
        viewBox: pack.viewBox,
        surface: pack.surface,
      };
      let svg: string;
      try {
        svg = renderSvg(spec, { size: 32, state });
      } catch (error) {
        throw new PackError(
          `${origin}: family ${family} colour ${color} ${state} failed to render (${(error as Error).message})`,
        );
      }
      if (!svg.startsWith("<svg") || !svg.endsWith("</svg>")) {
        throw new PackError(`${origin}: family ${family} colour ${color} ${state} is not an svg`);
      }
      for (const token of BAD) {
        if (svg.includes(token)) {
          throw new PackError(
            `${origin}: family ${family} colour ${color} ${state} contains ${token}`,
          );
        }
      }
    }
  }
  return { rendered: selected.length * 2, sampled };
}
```

Note the import cycle: `conformance.ts` imports `PackError` from `packs.ts`, and `packs.ts` will import `assertPackRenders`. Keep `PackError` in its own module if the cycle causes trouble: move it to `apps/service/src/pack-error.ts` and re-export from `packs.ts`. Prefer moving it; a cycle between the two is a smell even when it works.

```ts
import type { StylePack } from "@botavatar/engine";
import { createHash } from "node:crypto";
import { identityHash } from "./respond.js";

export interface TagInput {
  packHash: string;
  identity: string;
  size: number;
  state: string;
}

/** Opaque cache tag: a hash over hashes. No pack or identity text can appear in it. */
export function avatarTag({ packHash, identity, size, state }: TagInput): string {
  const digest = createHash("sha256")
    .update(`${packHash}|${identityHash(identity)}|${size}|${state}`, "utf8")
    .digest("hex")
    .slice(0, 16);
  return `"${digest}"`;
}

export function matchesIfNoneMatch(header: string | undefined, tag: string): boolean {
  if (!header) return false;
  const wildcard = header.trim() === "*";
  if (wildcard) return true;
  return header.split(",").some((entry) => entry.trim().replace(/^W\//, "") === tag);
}

export function packHeader(pack: Pick<StylePack, "id" | "version">): string {
  return `${pack.id}@${pack.version}`;
}
```
