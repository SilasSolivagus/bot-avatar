# 契约 v2：把"SVG 字段表"换成"角色几何"

日期：2026-10-28　状态：设计提案（未实现）
背景：吸收清单见 `2026-10-28-eye-rig-absorption.md`

## 0. 一句话

现在的 `AvatarSpec` 把角色写成了 SVG 的属性。v2 把它写成**几何与姿态**，让同一个角色可以被三种渲染器画出：SVG、PNG、三维。

## 1. 诊断：契约里缺什么

| 现状字段 | 它替谁做了决定 | 后果 |
| --- | --- | --- |
| `path: string` | "用 SVG 的 `<path>` 表达身体" | 喂不了 three.js，也无法做形状插值 |
| `eyes: rect[]` | "眼睛是两个矩形" | 球面投影、眨眼、眼神都表达不了 |
| `eyeRotation: number` | "整组转一个角度" | 单眼倾斜、注视方向无法表达 |
| `color.light/dark/eye` | "颜色是十六进制，眼睛涂一个色" | 无法随界面反转，无法做"眼睛是洞" |
| 无 | 配件 | 没有位置挂任何东西 |
| 无 | 姿态 | 只有一个 `idle`/`working` 的 CSS 动画，取不出"某一刻" |

**问题不在字段少，在于字段的"单位"错了**：它记的是**画法**，不是**角色**。

## 2. 四条设计原则

1. **几何，不是标记。** 身体是点集与曲线类型；渲染器负责变成 `d`、变成三角形、变成网格。
2. **墨，不是色号。** pack 声明"角色用什么墨、眼睛露出什么表面、点缀用什么强调色"，由渲染器解析成具体颜色。
3. **姿态，不是动画。** 时间是纯函数 `sample(state, t)`，随时可以取一帧；动画与静图是同一条曲线的两种用法。
4. **构造，不是风格。** 形状、眼睛、配件是三种可组合的构造维度；「风格」是它们的组合结果，不是一个大对象。

## 3. 新契约

```ts
// ---- 身份与缓存（沿用 v1，不变） ----
interface AvatarIdentity {
  packId: string;
  packVersion: string;
  identity: string;
  seed: number;
}

// ---- 身体 ----
type Curve = "smooth" | "hard";           // smooth: 现有 Catmull-Rom；hard: 直线折角
interface Body {
  outline: readonly Point[];              // 120×120 坐标系，闭合，原点居中
  smoothingPasses: number;
  curve: Curve;
}

// ---- 眼睛 ----
interface Eye {
  /** 在球面上相对注视点的横向/纵向角度，度 */
  lateralDeg: number;
  verticalDeg: number;
  /** 胶囊半轴，单位与 outline 相同 */
  halfWidth: number;
  halfHeight: number;
  /** 每只眼睛自己的倾斜，度；注意长宽比规则 */
  tiltDeg: number;
}

interface EyeRig {
  sphereRadius: number;                   // 与 outline 同单位
  eyes: readonly [Eye, Eye];
  /** 球面渲染的淡出/剔除阈值，归一化深度 */
  fadeFromDepth: number;
  cullAtDepth: number;
}

// ---- 表情与姿态 ----
interface Pose {
  gaze: { yaw: number; pitch: number };   // 度；绝对方向，不是相对偏移
  /** 眨眼：1 全开，0 全闭；作用在投影之后的竖直方向 */
  lidOpen: number;
  /** 表情对眼睛尺寸/倾角/开合的乘数，逐项可选 */
  expression?: Partial<Record<"width" | "height" | "tilt" | "open", number>>;
}

// ---- 配件 ----
interface Accessory {
  kind: "badge" | "antenna" | "ring" | "arc";
  /** 挂在轮廓上的角度，度；位置由轮廓在该角度的真实半径算出 */
  atDeg: number;
  scale: number;
  span?: { fromDeg: number; toDeg: number };  // 弧类配件
  /** 位于身体之前或之后，决定遮挡关系 */
  layer: "behind" | "front";
}

// ---- 墨 ----
type InkRole = "ink" | "surface" | "accent";
interface Ink {
  body: InkRole;
  eyes: InkRole;
  /** 可选的口部/配件颜色，语义同上 */
  detail?: InkRole;
}

// ---- 总装 ----
interface AvatarGeometry extends AvatarIdentity {
  body: Body;
  rig: EyeRig;
  pose: Pose;
  accessories: readonly Accessory[];
  ink: Ink;
  /** 兼容层：直接给出时优先于 ink，用于老 pack 的固定配色 */
  palette?: { light: string; dark: string; eye: string };
}
```

## 4. 球面投影：把 `(yaw, pitch)` 变成一只眼睛的变换

这是 v2 里唯一真正新的数学，也是"看起来像活的"全部来源。

设注视方向由两个角给出（**绝对方向**，不是相对偏移）：

```
f = (sin(yaw)·cos(pitch),  sin(pitch),  cos(yaw)·cos(pitch))      // 单位向量，+z 朝观察者
r = normalize(cross((0,1,0), f))                                   // 屏幕右
u = cross(f, r)                                                    // 屏幕上
```

第 i 只眼睛在球面上的位置，用相对注视点的横向角 `sᵢ` 与纵向角 `eᵢ` 表示：

```
nᵢ = normalize( cos(eᵢ)·(cos(sᵢ)·f + sin(sᵢ)·r) + sin(eᵢ)·u )
pᵢ = R · nᵢ                      // 球面上的点，R 为球半径
屏幕位置 = (pᵢ.x, pᵢ.y)           // 正交投影：丢掉 z
```

切平面基（投影后就是那 2×2 矩阵）：

```
tᵢ = normalize(cross((0,1,0), nᵢ))
bᵢ = cross(nᵢ, tᵢ)
屏幕基向量 = (tᵢ.x, tᵢ.y) 与 (bᵢ.x, bᵢ.y)
```

眼睛的 SVG 变换（渲染器可直接输出 `matrix`）：

```
M = [ tᵢ.x·w,  bᵢ.x·w·lid
      tᵢ.y·w,  bᵢ.y·w·lid ]          平移 (pᵢ.x, pᵢ.y)
```

其中 `w` 是半宽，竖直方向乘以 `lidOpen` —— **眨眼是屏幕竖直方向的压扁，发生在倾斜之后**，这与测量一致。

深度与淡出：

```
depthᵢ = nᵢ.z
alpha  = clamp( (depthᵢ - cull) / (fadeFrom - cull), 0, 1 )
```

**为什么这能自然地产生"远的那只更窄"**：`tᵢ` 投影到屏幕后的长度是 `√(1 - tᵢ.z²)`，眼睛越靠球面边缘，`tᵢ.z` 越大，矩阵越窄。不需要任何"把远处眼睛画小"的特判。

**`tiltDeg` 与缩放的顺序**：先由切平面矩阵决定朝向与压缩，再叠加每只眼睛自己的 `tiltDeg`，最后乘 `lidOpen`。顺序错了，眨眼会沿胶囊长轴发生，看起来像"眼睛变窄"而不是"闭上"。

## 5. 形状：点集 + 曲线类型，外加脸部锚点

- 身体仍是闭合点集，`curve` 决定渲染成平滑曲线还是硬折线（这是我们现在缺的一个维度：粘土包想要"硬边"，只能靠 `smoothingPasses: 0` 近似）。
- **每个形状可带脸部锚点** `face: { dx, dy }`：非对称形状（水滴、星形）上，眼睛不能按包围盒居中。
- **形状插值**：两个形状点数相同时，逐点线性插值；点数不同时，先重采样到固定数量（`RESAMPLE = 64` 个等角点，仅适用于相对中心星形的形状；非星形形状只能"硬切"或走形状变形）。
  这条限制必须写进契约：**不是所有形状都能平滑过渡**，能过渡的是明确标注的那一类。

## 6. 姿态：`sample(state, t)` 与 `posterAt(state)`

```ts
type AvatarState = "idle" | "thinking" | "working" | "waiting" | "blocked" | "done";

interface PoseSource {
  /** 纯函数：给定状态与时刻，返回一帧姿态 */
  sample(state: AvatarState, t: number): Pose;
  /** 该状态的代表帧，用于静态渲染 */
  posterAt(state: AvatarState): Pose;
}
```

- 动效由**每通道独立的低幅正弦**构成，频率故意不成整数比，所以看不出循环点。
- 渲染器要静图就取 `posterAt`；要动图就把 `sample` 采样成 8–12 个关键帧交给 CSS。
- **`posterAt` 是新增的必要概念**：没有它，"这个 bot 正在思考"这种静图就不存在。

## 7. 墨：由 pack 声明角色，由渲染器解析颜色

```ts
interface InkRoles { body: InkRole; eyes: InkRole; detail?: InkRole }
```

| 渲染场景 | `ink` 解析成 | `surface` 解析成 |
| --- | --- | --- |
| 网页（跟随主题） | `currentColor` | 挖空，透出背景 |
| PNG / 服务端 | 明确的深色（可配置） | 明确的背景色（请求参数） |
| 三维 | 材质的基础色 | 背景/环境色 |

**约束**：`eyes: "surface"` 意味着挖空，**服务端必须知道背景色**。所以 v2 规定：`paint` 为挖空时，PNG 请求必须带 `bg`，否则 400 并说明原因。这条不能默认，因为"猜一个背景色"会产生错误的缓存。

## 8. 渲染器接口

```ts
interface GeometryRenderer<Out> {
  render(geometry: AvatarGeometry, options: RenderOptions): Out;
}

interface RenderOptions {
  size: number;
  /** 挖空眼睛时必需 */
  surface?: string;
  reducedMotion?: boolean;
}
```

三种实现共用同一份 `AvatarGeometry`：

- `svg`：几何 → `d`、`matrix`、`mask`、CSS 关键帧
- `png`：`svg` 的输出交给栅格器（保持"一条渲染路径"）
- `three`（将来）：几何 → 形状路径挤出、眼睛 → 贴图平面、配件 → 图元

## 9. 迁移：v1 不废，走适配器

**永远保留 v1 渲染器。** 老 pack 的输出必须逐字节不变，否则：

- 已缓存的 SVG 会被新字节替换，但 `immutable` 让客户端不来取
- 110/110 的上游复刻证据作废

```ts
// packs/organic-blob-v1 继续用旧契约
// 新 pack 声明 geometryVersion: 2
function toGeometryV2(specV1: AvatarSpec): AvatarGeometry
```

适配器把 `path` 反向解析回点集是不必要的；更实际的做法是**pack 同时携带 v1 与 v2 数据**，由同一份源生成。organic-blob 的点集本来就存在，加个转换即可。

## 10. 缓存与确定性

v2 让"渲染器变更"变成常态，所以**ETag 必须包含渲染器构建指纹**：

```
ETag = hash(packContentHash | identityHash | size | state | surface | renderBuild)
```

`renderBuild` 在构建时由 `engine/src` 与 `renderer-svg/src` 的哈希决定。没有它，改渲染器等于对老用户不可见（一轮 `immutable` 就是一年）。

## 11. 会破什么

| 项 | 影响 |
| --- | --- |
| `AvatarSpec.path` | 保留给 v1 渲染器，v2 新增 `body.outline` |
| 现有 5 处眼睛断言 | 必须改成断言 v2 的矩阵与姿态 |
| `conformance` 手工构造 spec | 增加 v2 构造分支 |
| `parsePack` | 校验 `rig`、`accessories`、`ink`，并检查长宽比-倾角规则 |
| 服务 PNG | 挖空模式要求 `bg` 参数 |
| 110/110 证据 | 仅对 v1 渲染器成立，文档口径要改 |
| 版本号 | organic-blob 保持 1.x；新包从 2.0.0 起 |

## 12. 分四步落地

1. **v2 类型 + 适配器**：新增类型，`toGeometryV2`，v1 渲染器不变，输出零差异。
2. **SVG 渲染器 v2**：球面眼睛、mask 挖空、`posterAt` 静图。以新包验证，老包仍走 v1。
3. **墨模式包**：`ink` 构造，`currentColor` + 挖空，验证"一套几何、深浅两副面孔"。
4. **渲染器构建指纹进 ETag**：这一步可以在第 2 步之前单独做，越小越好。
